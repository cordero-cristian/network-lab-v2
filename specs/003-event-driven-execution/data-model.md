# Data Model: Event-Driven Durable Execution

## Shared Scalar Rules

- **EventId / CorrelationId**: UUID values; request IDs are generated by the caller,
  result IDs by deterministic workflow-safe APIs.
- **DeviceName**: Reuse Feature 002's stripped safe name matching
  `^[A-Za-z0-9][A-Za-z0-9._-]*$`.
- **UtcTimestamp**: timezone-aware datetime whose UTC offset is zero; JSON emits `Z`.
- **SourceText**: stripped text from 1 through 64 characters.
- **ErrorMessage**: stripped safe text from 1 through 256 characters; never populated
  by blindly copying raw exception text.
- **WorkflowId**: stripped text from 1 through 128 characters.
- All models are frozen and reject unknown fields.

## RenderDeviceConfigRequest

| Field | Type | Validation |
|---|---|---|
| `event_id` | EventId | Source request event ID |
| `correlation_id` | CorrelationId | Source correlation ID |
| `device_name` | DeviceName | Source exact target |

Its derived workflow ID is `render-device-config:<event_id>`. It contains no source,
timestamp, raw intent, configuration text, topic, or transport offset.

## State Transitions

```text
Kafka request uncommitted
  -> invalid -> safe log -> offset committed
  -> valid -> workflow start/attach attempt
       -> transport uncertainty -> same offset sought, remains uncommitted
       -> accepted/already exists -> offset committed

Workflow started
  -> render activity retries transient failures
       -> success -> completion created -> publication retries -> completed outcome
       -> permanent/exhausted -> failure created -> publication retries -> completed failure outcome
  -> result publication exhausted -> workflow failed visibly
```

Duplicate Kafka records do not transition to a new workflow while workflow history is
retained because workflow identity rejects reuse. A repeated physical result record
has the same result `event_id` and represents the same logical outcome. Replay after
Temporal's configured retention expires is not modeled.

## Ownership

Nautobot remains the owner of intended state. Kafka owns transport records and
consumer offsets. Temporal owns workflow state, retries, and recovery. Feature 002
owns validated intent, deterministic rendering, and atomic artifact behavior. Event
models describe facts only and own no external I/O.
